# 数字代表临时模式与会话边界

2026-10-15，第十批。玻璃材质已达到当前 Windows 本机验收标准，本批返回数字代表开发主线，落实原方案 F03、F04、F08 与第四周的隐私控制、异常状态和晚到任务保护。

## 本批范围

不扩大自动采集类别，不新增模型调用或付费服务。先修正取消请求、临时模式、界面回读和主窗口重载的边界，再继续后续画像与评测能力。

| 操作 | 当前语义 |
| --- | --- |
| 停止本次生成 | 取消请求和未提交的旧学习，保留临时模式及已有学习暂停保护 |
| 明确清空对话或切换临时模式 | 开始指定模式的新对话，取消旧上下文，回读主进程确认状态 |
| 页面内部切换或同文档导航 | 保留当前登录；模式仍由主进程确认 |
| 整页刷新或主渲染进程退出 | 结束当前登录、取消旧任务并清理运行期状态；重新登录后读取原有加密资料 |

整页刷新不是自动保存或恢复聊天的入口。当前产品原本就会在刷新后回到登录页，本批使主进程与这一界面行为一致；没有新增自动登录、聊天历史落盘或临时模式跨登录持久化。

## 关键修正

### 将取消与模式变更分开

原 `ai.cancel()` 的默认 false 会把取消请求解释为退出临时模式，并清掉本次学习暂停。现在无参数仅取消；只有明确的布尔参数才表示开始指定模式的新对话。私密试答的“停止”使用纯取消，不解除对话语境保护。

### 返回主进程实际模式

代表状态结果在持久 `state` 之外增加运行期 `temporary`，与已有 `learningPaused` 一样不写进加密账户结构。界面在读取、修改和待续操作后统一同步主进程状态，不依据首次挂载的 false 推断当前模式。

初次状态未确认时，发送、私密试答和临时模式操作保持禁用。切换模式先移除旧的可见状态，再回读。读取失败或缺少模式信息时，保持禁发并提供重试，不默认恢复普通模式。输入框中未发送的文字不因普通模式切换而丢失。

### 临时响应不携带长期正文

临时模式下，发送到渲染界面的状态副本将记忆和待续数组投影为空，不返回恢复草稿正文。界面显示“长期记忆已隐藏”，不会把隐藏误报为删除或零条原始记忆。退出临时模式并成功回读后，原资料重新可见。

投影不写回持久存储。主进程仍需要读取授权和已有加密状态来判断权限；本批不宣称临时模式是零磁盘读取、清除全部进程内存或没有供应商处理。模型仍需用户独立授权，只处理当前输入与必要上下文，不采用临时模式下的长期偏好。

### 作废跨模式与跨文档旧任务

状态读取、修改、待续、回复、试答及状态通知同时检查账户会话与对话版本。临时模式或会话变更后，未完成的旧操作必须通过新守卫；失效的正文或通知不返回当前页面。

主窗口新主文档导航和渲染进程退出复用已有会话清理。同文档、子框架和伴生窗口事件不误清主登录。已经合法提交的长期资料不会因为进入临时模式而被删除；也不承诺撤回已发送给供应商的数据。

## 验证

`pnpm test:session` 增加确定性测试：临时响应脱敏且不改原状态，运行期字段不进入持久结构，三类状态 IPC 跨模式失效，无参取消保持临时与暂停，前端旧读取不能覆盖新模式，读取失败禁发，导航与渲染退出结束旧登录，子框架及同文档不误登出，旧登录请求不能跨文档生效。

`pnpm smoke:representative` 增加隔离 Electron 流程：主动保存虚构片段，进入临时模式检查返回与界面均不含长期正文，直接保存/恢复被拒绝，纯取消保留模式，同文档导航保留登录，整页刷新后未登录不能读资料，重新登录恢复加密偏好与待续，云端授权保持撤回。该流程不发模型请求，结束后仅移除自己的测试片段。

原有玻璃实际像素、交互合帧、缩放、私密试答、草稿、撤权、删除恢复和外观容错回归继续保留。相关截图只使用隔离账户；没有真实用户资料或登录密码。

本轮 `pnpm check`、源码窗口和真实打包程序的完整回归、便携 EXE 启动退出及包内审查均已通过。实际打包报告的 `temporaryPrivacy` 各检查通过，新增模型请求为 0；玻璃中心像素差仍为 0，交互合帧预算继续通过。程序与校验文件使用新的独立时间戳目录，不覆盖此前版本。

## 上传前复核：保留操作失败反馈

2026-10-15 追加源码修复：修改授权、忘记偏好或重置失败后，先恢复读取主进程状态，再保留本次操作的失败提示；恢复读取也失败时，同时保留两类错误并清空可用状态，禁止发送。重置只有确认成功才关闭确认界面，失败保留重试入口。卸载后不写回迟到提示。

确定性测试覆盖恢复成功、恢复失败、重复操作、卸载后的晚到更新及读取；在内存中还原旧执行顺序时，新测试按预期失败。隔离 Electron 回归通过真实版本冲突触发失败，验证错误持续可见、原记忆未删、确认未关闭，重试成功后才清除提示；未增加模型请求。追加修复仅进入源码，没有重打包第十批 EXE。
