# Aociety：Liquid Glass 交互与调度优化

2026-10-15，第九批。在第八批材质上减少重复工作、补齐取消边界，不更换视觉方向。

## 改了什么

- 指针事件只保存最新视口坐标。到下一帧时，读取一次控件当前布局，再写入高光位置；不再为每个事件单独读取布局。
- 多个玻璃控件更新尺寸时，先集中读取全部几何数据，再生成贴图、更新 SVG 和样式，避免自身的读写交错。
- 离开、取消、触摸移动、触摸按下、容器滚动、窗口缩放和失焦会取消未执行的高光更新，并清理已显示的位置。窗口失焦不会锁住按钮或改变草稿。
- 帧回调再次确认目标仍存在、可见且具有有效材质。事件之后、绘制之前发生位移时，按最新布局换算坐标；目标隐藏或材质失效时不再写入。
- 保留第八批折射、高光、减少动态效果、清晰和系统高对比回退。没有新增依赖、全屏动画、强制等待或用户数据采集。

本批沿用 Apple Design 的即时反馈与可取消交互原则，按 Impeccable 的“测量、优化、复测”顺序推进。未重新设计页面，也不为性能简化而移除用户已经要求的玻璃效果。

## 前后证据如何理解

修改前，先在隔离源码程序记录基线；随后改动生产组件，再在同类环境运行相同检查。240 个指针事件同步进入同一帧预算：

| 检查项 | 第八批基线 | 第九批源码复测 |
| --- | --- | --- |
| 布局读取 API 调用数 | 240 | 1 |
| 高光位置写入数 | 2（x、y） | 2（x、y） |
| 位移图重新编码数 | 0 | 0 |
| 取消、触摸、滚动、缩放、失焦残留 | 除离开外仍有旧高光或待写入 | 所有新增清理检查通过 |

这证明减少了重复布局读取，不等于减少了 239 次强制重排，也不表示用户帧率提升 240 倍。高频事件通常分布在多个实际帧中；此处刻意集中到同一帧，用来验证合并行为。

基线记录带有 `enforced: false`，表示先观测而非要求旧版满足新预算；新版验收必须为 `enforced: true`。基线与复测 JSON 随资料保存，当前实际打包程序的结果另见 `representative-smoke.json` 的 `liquidGlassInteraction`。

第九批实际打包程序也已通过同一预算：1 次布局读取、2 次位置写入、0 次位移图编码；七类清理和三个目标竞态全部通过。原有折射像素对照仍通过且中心差为 0，完整功能回归、便携启动退出及 ASAR 审查通过。新产物使用独立时间戳目录，不覆盖第八批。

## 验证范围

新增测试只运行在隔离 Electron 账户，不进入发布包：

- 240 事件合帧、最后坐标生效、一次布局读取、两次位置写入、零贴图重编码。
- 七类清理事件在“尚未绘制”和“已经显示”两阶段均不留下位置或晚到写入。
- 事件到帧之间的 4px 平移、材质属性失效、目标隐藏三个竞态分支。
- 连续 12 个稳定空闲帧不写高光、不重新编码。
- 原生输入、键盘选区和草稿保留；测试期间不增加模型请求。
- 自动化鼠标移动期间采样 60 个帧间隔。只记录当前机器与本轮环境，不视为实体鼠标/触控验收或跨显卡帧率认证，也不把软件绘制与正式 GPU 路径直接作速度比较。

旧有折射实际像素对照、中心稳定、缩放、清晰/强制颜色、账户、授权、画像、草稿、试答与外观容错回归继续保留。最新独立 EXE、校验值与启动检查见 `LOCAL_ACCEPTANCE.md`。
